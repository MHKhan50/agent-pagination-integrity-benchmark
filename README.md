# Agent Pagination Integrity Benchmark (APIB) v0.1.0

**Research question:** When a tool-using agent retrieves a collection through cursor-based pagination, how often do common stopping and verification policies falsely declare the collection complete under empty-but-nonterminal pages, duplicate/omitted records, missing pages, and cursor cycles?

## Scope and scientific claim

APIB is a deterministic synthetic benchmark of pagination-control policies. It does **not** measure a deployed LLM or prove that a particular model behaves this way. It isolates a narrow agent-tool orchestration failure: confusing a partial page with a complete collection, failing to follow continuation cursors, or declaring completeness without reconciling unique records against an expected count.

## Policies

- `first_page_only`: retrieves one page and claims completion.
- `stop_on_empty`: incorrectly treats an empty page as end-of-collection.
- `follow_cursor`: follows continuation cursors, detects cursor cycles, but does not reconcile unique record count.
- `count_verified`: follows cursors, deduplicates record IDs, detects cycles, and reports completion only when the cursor chain is exhausted and unique count matches the expected total.

## Synthetic conditions

`stable`, `empty_nonterminal`, `duplicate_omission`, `missing_page`, and `cursor_cycle`. Each episode has a known expected record count and deterministic page map. The data are self-generated, not collected from users or external APIs.

## Metrics

- **Mean coverage:** unique retrieved IDs / expected total.
- **False-completion rate:** incomplete episodes incorrectly reported complete / all episodes.
- **Incomplete-detection rate:** incomplete episodes correctly reported incomplete / all incomplete episodes.
- **Correct-completion rate:** complete episodes correctly reported complete / all episodes.
- **Mean tool calls:** page requests per episode.

## Reproduce (Python 3.9+, standard library only)

```bash
python3 -m unittest discover -s tests -v
python3 benchmark.py --n-per-seed 600 --seeds 17 29 43 71 101 --out results
```

The default experiment contains 3,000 episodes, 5 seeds, 5 scenario types, and 4 policies (12,000 policy evaluations).

## Files

- `benchmark.py`: generator, simulator, and evaluation.
- `data/`: self-generated Kaggle-ready episode table and provenance note (generated by the run).
- `results/`: precomputed results from the packaged reference run.
- `tests/`: automated tests.
- `notebooks/APIB_Kaggle_Colab.ipynb`: analysis notebook compatible with Kaggle and Colab when the project files are present.
- `docs/experimental_protocol.md`: protocol and limitations.

## Limitations

The simulator assumes the expected total is available to the agent, does not model real network latency or API-specific token expiry, and uses a finite set of hand-designed fault modes. A later study should test live API adapters and LLM-driven agents under controlled conditions. The current benchmark's results are policy-simulator baselines only.

`count_verified` reaches 0% false completion by construction: it only reports completion when the unique count equals the expected total, which the simulator gives it. The useful findings are the size of the gap for the other policies and the fact that count checking changes the completion claim but not coverage (94.8% for both cursor-following policies). A harder version should hide or perturb the expected total.
